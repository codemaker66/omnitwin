# D-016a — Training environment: PyTorch 2.14.1 and gsplat main, with PPISP on trial

Status: proposed (environment validation pending, T-655)
Date: 2026-10-13
Authors: Blake (direction), Claude (T-655)
Supersedes: none yet. If accepted, it replaces D-016's trainer environment pins only (gsplat 1.5.3, PyTorch 2.4.1, CUDA 12.4); D-016's decision that splat training runs on RunPod stands either way.
Depends on: D-016, D-006a

## Context

Blake, 13 October 2026, verbatim: "Upgrrade the splat and pytorch to the latest and inform our repo we are doing so, multiple sessions may need that info. Try PPISP."

What "latest" meant on that day, checked at the source:

- PyTorch 2.14.1 (PyPI, 30 September 2026) with torchvision 0.29.1. The official Linux wheels come in cu126, cu130 and cu132 builds; the default PyPI wheel is the CUDA 13.0 build.
- gsplat's newest release is still 1.5.3 (4 July 2025). GitHub `main` is ahead: `512d366b67073d77ca099ede742683c165dfc23b` (19 September 2026, version string 1.6.0, unreleased). It carries the PPISP post-processing in `examples/simple_trainer.py` (`--post_processing ppisp`, pinning `ppisp@v1.2.1`) and, since July 2026, PPISP with the MCMC strategy.
- PPISP (NVIDIA, CVPR 2026, arXiv 2601.18336, `nv-tlabs/ppisp`, Apache-2.0) models per-frame exposure and a colour homography, per-camera vignetting and a camera response curve, plus a controller that predicts exposure and colour for views it never saw. Its newest tag is v1.3.0 (`a247368047651db2e03e6f97a36e4f5bebbe5c5f`, 23 September 2026): the same API as v1.2.1 with faster kernels, an exact CRF backward and a fix for misaligned pixel coordinates.

The panorama splat lane does not train through the `omnitwin/trainer` image. Its pods use RunPod's own PyTorch image and install gsplat at boot (`D:/claude/pano-splat-20261003/pod_boot.sh`: `runpod/pytorch:2.4.0-py3.11-cuda12.4.1-devel-ubuntu22.04`, `gsplat==1.5.3` compiled on first use for sm_90).

## Proposed decision

The target environment for new splat training:

| Component | Target pin |
|---|---|
| PyTorch / torchvision | 2.14.1+cu130 / 0.29.1, official `cu130` wheels (`https://download.pytorch.org/whl/cu130`) |
| CUDA toolkit | 13.0 |
| Host driver | supports CUDA 13.0 (driver 580 or newer; RunPod `allowedCudaVersions: ["13.0"]`) |
| gsplat | built from source at `main` `512d366b67073d77ca099ede742683c165dfc23b` (`--no-build-isolation`, `BUILD_EXPERIMENTAL=0`) |
| PPISP | `nv-tlabs/ppisp` v1.3.0, `a247368047651db2e03e6f97a36e4f5bebbe5c5f` (`--no-build-isolation`) |
| Python | 3.12 |

PPISP is an opt-in trainer flag in the trial; default recipes do not change.

3DGUT needs a separate build. The trainer uses gsplat's classic 3DGS rasterization only, so the trial builds gsplat with `BUILD_3DGUT=0`, which leaves out the 3DGUT ("from world" / unscented-transform) kernels. Those kernels dominated the full build: about 35 of its 40 minutes on the first pod. Work that needs 3DGUT builds gsplat without that flag.

## Validation status (13–14 October 2026)

- Done: on a RunPod H100 SXM pod (driver 580.126.09, CUDA 13.0, nvcc 13.0.88, Python 3.12.3), PyTorch 2.14.1+cu130 and torchvision 0.29.1+cu130 installed and ran on the GPU, and gsplat `main` @ `512d366b` compiled in full, 3DGUT included, for sm_90 and installed (2,418 s).
- Not yet done: the PPISP build, gsplat's and PPISP's forward/backward checks, PPISP's own test suite and the 200-step smoke runs of the panorama trainer. The pod stopped at 23:27 UTC before reporting them; its logs are being retrieved and the failure fixed before the next run.
- Until the smoke test passes, the RunPod image pins stay unchanged: `infra/runpod/Dockerfile` still describes `omnitwin/trainer:1.5.3-cu124` (gsplat 1.5.3, PyTorch 2.4.1, CUDA 12.4). A follow-up change moves those pins and marks this ADR accepted.

## Consequences

- Old recipes stay reproducible on their own pins (gsplat 1.5.3 on PyTorch 2.4). Results from the two environments are compared as such, not mixed silently.
- gsplat `main` is unreleased, so the commit is the version. Every run records its versions (the panorama trainer writes them to `run_config.json`), and an upgrade past `512d366b` needs a new smoke run.
- CUDA 13.0 needs a 580-series driver. Pods must request CUDA 13.0 hosts; cu126 wheels remain the fallback for older drivers, with a matching CUDA 12 toolkit for the gsplat build.
- The RunPod-only rule of D-016 is unchanged. No splat training moves to the local PC.

## Alternatives considered

- **Stay on gsplat 1.5.3 and PyTorch 2.4.1.** No PPISP, and a CUDA 12.4 toolchain that newer PyTorch builds have left behind. Kept only for reproducing old results.
- **cu126 wheels.** They run on older drivers, but they are not PyTorch's default build, and RunPod H100 SXM hosts with CUDA 13.0 drivers are available.
- **cu132 wheels.** Newest, but RunPod's host filter tops out at CUDA 13.0.
- **PPISP v1.2.1**, the version gsplat's example pins. Same API; v1.3.0 adds correctness fixes.
- **Waiting for a gsplat 1.6.0 release.** No release date is published; the pinned commit gives the same reproducibility.
