# Reception Room quality decision matrix

**Handling:** INTERNAL / public-redaction-required. Remove or approve exact local paths, identifiers, hashes, station bounds, pricing captures, and venue imagery before external sharing.

**Evidence cutoff:** 2026-07-22

**Decision rule:** correct proved zero-cost losses before buying or training; then use the same captured photo set and frozen cameras to compare vendor, independent, and layered candidates. “Expected gain” is a forecast until a candidate passes the stated falsifier.

**Names used below:** `Quality` and `Mobile` are vendor candidate/file labels, not quality judgments. The application code's older `Living Hall` room name points to this Reception Room asset; it is not a second room.

**Historical runtime result — 2026-07-16:** The two exact four-leaf private profiles still exist locally, and the runtime-package resolver and exact private-preview gate reject mixed replacement levels. A separate database-free, development-only route now exercises the real Living Hall scene component with one explicit renderer contract, `reception-fixed-fine-review-v1`. The Quality candidate loaded four SOG leaves and exactly 2,002,009 Gaussians; the Mobile candidate loaded four SPZ leaves and exactly 1,978,258 Gaussians. This is decoded-count evidence in the local component, not proof of the bytes served by the protected route. No candidate has been deployed, registered, streamed through the protected authenticated route, selected as the winner, or used to change the public pointer.

The local runtime delivery contract was subsequently hardened without changing those capture receipts. The exact byte-profile allowlist of IDs, filenames, hashes, storage receipts, hierarchy and composition metadata remains in the API server and is absent from the public response and production bundle; authenticated administrator preview metadata remains a separate private path. Neither reviewed byte profile is an anonymous presentation candidate. Quality SOG and Mobile SPZ have reviewed four-member byte identities, but neither has an exact reviewed immutable presentation contract, so the public Living Hall currently receives no profile or member URL. A future contract must bind the exact group transform, camera policy and route, and renderer-profile digest, and the browser must apply those reviewed values exactly. Detailed package metadata and direct asset-ID streams are platform-admin-only, and the retired legacy browser resolver returns fallback. The older raw external-URL single-visual endpoint is retired for every room.

Reviewed objects must use dedicated private runtime-profile R2 credentials and a dedicated bucket with no public URL or legacy-storage fallback. Any future public metadata and byte request require the showcase switch, exact reviewed byte identity and presentation contract, published state, human-reviewed public QA and a linked signed transform scoped to the same package, venue and room. `approved_public` requires every required QA check to be present and `passed`; any other required-check status fails closed. QA binds the transform's exact SHA-256, transform and QA IDs are immutable except for exact retries, and the complete gate plus immutable member identity is re-read immediately before send. A cache miss verifies the full member's size and SHA-256; verified bytes may then live in a per-process 64 MiB / 16-entry / five-minute LRU, with single-flight for identical content but no shared authorization.

Each API process handles two verified responses at a time and safely queues 16 more in FIFO order. The queue wait is five minutes, the member limit is 16 MiB and the upstream limit is 30 seconds. A separate absolute 180-second response/transfer deadline aborts upstream work and destroys a stalled response; a slot is reused only after both handler work and response settlement complete. The administrator-only private-preview byte route now listens for disconnect before its database/package lookup, preventing a disconnect-during-lookup slot leak. The anonymous member route also limits each client IP to 24 requests per minute. Reception's showcase remains off and both byte profiles remain presentation-ineligible, so no public profile or member bytes are released. External activation still requires the reviewed immutable presentation contract and exact browser application, provisioning least-privilege private storage, copying and byte-verifying the reviewed objects, proving direct anonymous bucket access is denied, and adding edge rate-limit/WAF controls. This is an undeployed implementation result, not product-route evidence or public approval.

The re-sealed local run contains 24 lossless 1200×900 PNGs: six matched feature views × two candidates × two captures. All 12 static repeat pairs were byte-identical 500 ms apart after load. Pairwise computer vision found material edge and pixel differences in both comparison directions; each direction produced five `review` views and one low-edge `not_assessable` ceiling-moulding view. Full-frame similarity ranged from 26.912251 to 29.773793 dB PSNR, 0.941555 to 0.961395 SSIM and 0.025317 to 0.040604 RGB MAE. These numbers measure candidate-to-candidate difference, not physical accuracy or product improvement. The six views were taken from one camera position with different framings, so moving/orbit stability, spatially distinct views, performance, supported devices, protected-route behavior and a registered held-out reference remain open.

T-514 still proves only a non-training Config B checker; the real trainer remains runtime-blocked. Structural 3D computer vision found nine walls and two wall directions in both real inputs, but both failed `HORIZONTAL_ROOM_ENVELOPE_NOT_FOUND`, so E57 remains optional and unusable as an alignment authority until a reviewed room-only crop/boundary and independent controls exist. The asset-backed empty Reception Room contains timber doors/glazing, curtains/windows, columns/moulding, floorboards and small fixed wall features—not the earlier generic fireplace/chandelier/painting/table list.

**Current candidate reconciliation — 2026-07-22:** the 16 July matched-camera check slightly favoured Quality, but the locked 17 July method holdout slightly favoured Mobile, with reported relative effects of only 0.07%–1.38% and no calibrated human-visible threshold. The 18 July artifact diagnosis found Quality had 34.3%, 28.7% and 42.0% more near-white pixels in scans 126, 129 and 141, while the fine-detail-energy ranking changed by view. The 22 July blind replay produced a direct model-family conflict: OpenCV BRISQUE preferred Mobile in 14/15 conditions, PIQ BRISQUE in 13/15, and CLIP-IQA preferred Quality in 14/15; the families disagreed in 13/15 conditions. The controlling decision is therefore `no_stable_physical_or_commercial_winner`. No older directional lead may be cited alone as the current ranking.
