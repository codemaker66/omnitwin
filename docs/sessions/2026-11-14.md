### What the count found

One read-only transaction, counts only, nothing personal read and nothing written. Production holds very few
records of these kinds. Every record that must have an event and has none belongs to one chain: an enquiry that
has been worked, its one deal and its one sent proposal. Nothing is in doubt: no record reaches more than one
event, no enquiry has two deals, no link crosses venues. There is no agreement, no deposit request and no card
payment. Nobody can see an event through a plan they own. So the join is small, and the first real data is
whatever the Diary import brings.

### Decisions made, with reasons

- **Each record points straight at its event,** pinned to its venue by its key, in place of a general link
  table or a stricter lookup. It is the method holds and bookings already use, and the only one the database
  itself can hold.
- **An enquiry becomes its event when someone first works it** (Blake). One function is the only way it gets
  one, so two acts at the same moment make one event.
- **A link can be moved but never emptied,** and one event has at most one open deal.
- **The stage is worked out when read and stored nowhere,** so a payment or a signature never has to write to
  the event.
- **Six stages, four of them changing the database.** The design put every new table in its first migration.
  The plan lands each table with the code that writes it, so no table sits unused. Each still merges alone.
- **The production check reports and turns red; it does not block a release.** A fault in the data must never
  be able to block the release that fixes it.

### Found, not fixed (other owners)

- Opening a card payment checks that the proposal is still accepted before its transaction, not inside it.
  Withdrawing or archiving a proposal leaves its deposit request in force. Signing an agreement takes no lock.
  All three are for piece E.
- A proposal's share link has a "revoked" column and no route that sets it. Piece F.
- Pull request #247 (erase a person) finds a person's events through `events.opportunity_id`, which this piece
  retires in its last stage. The column is not dropped until #247 no longer reads it. Reported to the programme
  lead.
- The production check of the Diary's own rule was never scheduled. Stage 1 schedules it.
