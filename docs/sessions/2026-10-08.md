## T-644 — the Twin hop stall behind the GPU gate

PR #45's required GPU gate failed the Twin test that bounds a room hop's
longest main-thread task at 150 ms. Earlier runs showed master and the
29 September code failing the same way under load and passing 5/5 when the
machine was quiet, so the budget was deciding on load alone. Traces on the
gate's own stack (WSL2, ANGLE GL on Mesa D3D12, RTX 4090) named the work: each
4096x2048 base pano (~33.5 MB) went to the GPU in one synchronous
`initTexture`, a 136-165 ms task. Three paths did it: the neighbour pre-warm
slices, the arriving node's base swap and the parallax stage's first draw of
the hop target. A browser benchmark with a synthetic 4096x2048 bitmap put one
whole upload at 129-386 ms on that stack and 15-36 ms on the same card
through Chrome's D3D11 path.

New `packages/web/src/twin/texture-residency.ts` allocates a base without data
and fills it with 2 MiB sub-rectangle copies from the same ImageBitmap, at
most 8 MiB per step, with a GPU fence between steps so the command queue never
backs up. Same benchmark: 5.5-6.5 ms per step and no long task on the gate
stack, 200 ms to fully resident; 3-11 ms per step on D3D11. Unfenced strips
still stalled 51-71 ms once per texture, and 16 MiB steps 42-82 ms. Streamed
texels were byte-identical to a whole upload on both paths.

The warmer, PanoStage and ParallaxStage now upload through it. A hop draws a
base only once it is fully on the GPU, otherwise its preview. A moved-on warm
queue keeps its textures for 3 s, so the node just walked to still finds the
base prepared for it. Two intermediate designs failed on the gate stack and
were dropped:
- Streaming without the parallax change left a 137-151 ms task, traced to the
  parallax forcing a whole upload.
- Taking a decoded base during the hop kept the long task away but put the
  hop over its byte budget (362 KB against 360 KB): the warmer released the
  base mid-upload and the settle fetched it again.

A unit test also caught that React can batch the preview and base updates
together, which would have drawn a blank sphere while the base streamed.

Gate-stack comparison, one workspace with files swapped in alternating order,
three rounds: longest hop task 141-157 ms at the PR head and 0, 0, 70, 95, 0
and 0 ms with this change (0 means no task over 50 ms). Every run of the change
passed the hop's request and byte budgets.

Checks, run in WSL because Windows memory was exhausted by other sessions
(the local typecheck timed out after 25 minutes):

- Twin unit tests: 796 passed, 16 skipped;
- the new `e2e/twin-texture-residency.spec.ts`, byte-identical texels through
