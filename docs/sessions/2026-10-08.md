## T-647 — Venue sky (weather) feed

Blake decided on 29 September that the relit hall follows real weather, and on
8 October: "I'll get a Met Office key". Built `GET /venues/:venueId/sky?at=`
on branch `claude/t647-sky` for T-639 to read; the contract, sources, licences
and limits are in the [engineering note](../engineering/venue-sky.md).

Decisions:

- **Forecast product: Site-Specific Blended Probabilistic Forecast v2.** The
  brief's "site-specific v2, v1 retires 11 Nov 2026, v1 keys do not work on v2"
  is the DataHub notice for the BPF; the other site-specific product (Global
  Spot, `/sitespecific/v0`) has no v2 and no cloud cover at all. Values are the
  50th percentile; fog and precipitation chances come from the probability
  collection. Free plan: 55 calls a day, one site; the API refreshes every 4 h
  (24 calls a day) with a 40-call daily cap per process.
- **Keys are per product.** The DataHub FAQ says a key is unique to its
  subscription. The key Blake created for atmospheric models will be answered
  401 (`forecast_key_rejected`); the free BPF v2 subscription issues its own
  key. Env var name unchanged: `MET_OFFICE_DATAHUB_API_KEY`, header `apikey`.
- **Public route**, like `GET /venues/:id`: public weather at a public address.
  422 `VENUE_NOT_LOCATED` for a venue without coordinates; 503
  `SKY_UNAVAILABLE` when neither a forecast nor normals can be served.
- **Venue location by data migration** 0086 (schema plus a fill for
  `trades-hall-glasgow` only while empty), the repo's existing pattern for
  data-changing migrations; next free number after a check of every branch.

Blocked:

- **Normals.** HadUK-Grid 1991–2020 `mon-30y` files are listed publicly on CEDA
  but every download redirects to the CEDA login, so per the brief no generator
  was written and no normals are committed. Requests that need normals (no key,
  past dates, beyond the horizon) answer 503 until a generated file is added.
  Unblock: someone with a CEDA account downloads the five 1 km files (or
  authorises a token-based generator), or Blake approves another official
  open source.
- **Live forecast.** No live Met Office response has been seen; the test bodies
  follow the documented structure with synthetic numbers. Verify after the key
  is set with `pnpm --filter @omnitwin/api venue:verify-site -- --api https://api.venviewer.com`.

Production steps, not run here: apply migration 0086 before the API release
(schema first: venue routes select every column); Blake sets
`MET_OFFICE_DATAHUB_API_KEY` on Railway from a BPF v2 subscription; then run
the verifier.
