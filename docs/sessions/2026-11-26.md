# 26 November 2026

## The Grand Assembly's Escape case: a race in the hold, fixed (T-742, #489)

- The case "Escape snaps it to the true state at once" failed master CI once on 20 November (91d55c4c): the Skip was
  not found within 60 s. The cause was a race in the product, not a slow load. `floor/assembly/recall.ts` holds a
  saved layout's room empty until the Grand Assembly takes it over and lets it go 8 s after nothing it needs is on its
  way. The planner said nothing was on its way once the room was known and the Assembly's code had run, but the
  Assembly mounts only once the 3D view has built the hall, and that first build holds the page's main thread for
  seconds. On a slow runner the 8 s ran out first: the request was dropped, the layout shown as placed, and the show
  (and its Skip) never came. A slow phone would have lost the Assembly the same way.
- Evidence. The job logs of 261 CI attempts (12 to 26 November) put the whole case at p50 14.5 s and p99 22.2 s; its
  one failure ran the full 60 s, so a longer wait would not have helped, and in that job the cases either side of it
  were the slowest of the sample. A step-by-step log of each opening, now attached to every case, showed one 5.5 s
  long task right after the Assembly's code ran on a desktop, and 5 to 7 s from code to stage on CI's runner, against
  the 8 s limit. Holding the page for 12 s just after the Assembly's code runs fails the base every time on CI's runner
  (0/3, the master failure's own signature) and passes the fix (3/3).
- The fix: the hold now counts a stage the Assembly is not yet on (`onStage`) as on its way, up to its 45 s cap, and a
  3D view that could not start is no stage. New tests in `recall.test.tsx` and `PlannerScene.test.tsx` fail on the
  base and pass on the fix. With no retries on CI's runner the fix passed the three cases 96/96 and the Escape case
  100/100. An independent review found no blocking problem; its points on the opening log were taken.
- Seen in passing, not addressed: one probe lane's `chrome-headless-shell` crashed at launch (SIGSEGV in libdbus)
  before any test code ran.

## The tour's visual baselines can no longer pass a changed figure or word (T-758)

Pull request #490. The release lead's rule: a screenshot baseline is never the only proof of a figure or a word.

### What hid the figure

On 24 November `twin-visual.spec.ts` passed all three rooms images with the Reception Room's size removed from its
line (record-baselines run 45500187056). Measured on 26 November with Playwright 1.59.1's own comparator over the two
sets of images the CI runner recorded either side of that change (runs 45081837681 and 45500757350):

| | desktop 1440 × 900 | mobile 390 × 844 | landscape 844 × 390 |
|---|---|---|---|
| pixels whose bytes differ | 237, in a 72 × 8 box | 237 | 0 |
| over the 0.2 threshold | 163 | 163 | 0 |
| counted by pixelmatch at 0.2 | 89 | 89 | 0 |
| counted at threshold 0 | 103 | 103 | 0 |
| budget of `maxDiffPixelRatio 0.0005` | 648 | 164 | 164 |

- The ratio hid the figure. The threshold did not: most changed pixels were over it.
- Pixelmatch's anti-alias detection, always on in `toHaveScreenshot`, set aside 74 of the 163.
- At 844 × 390 the row was below the panel's fold, so no screenshot setting could see it.

### What changed

- Every word and figure the HUD draws is asserted as DOM text in all twelve twin-visual cases, before the image is
  compared. Each string comes from the module the UI renders it from. A room's figures line and the dossier's stats
  are rebuilt from venue truth without the panels' formatters (`e2e/support/twin-hud-text.ts`).
- A coverage sweep then fails on any drawn text that no assertion covered, so a label added later is not pinned by
  the image alone.
- The words of the Rooms panel, the dossier and the quick-action rail move, byte for byte, into plain copy modules
  beside their components. The components import their stylesheets, which Playwright cannot load. `twin-tour.spec.ts`
  now imports the strings it used to paste.
- The image budget is an absolute zero (`maxDiffPixels: 0`; the threshold stays 0.2).
- `record-baselines.yml` records with `--update-snapshots=all`. With `changed`, an image that still passed within the
  tolerance was never refreshed until someone deleted it. `all` rewrites any image whose bytes differ, and only those.
