# Session log — 2026-09-01

## Day Board S1 shipped (T-556) — `/hallkeeper/today`

Slice 1 of the Day Board programme (`docs/plan/hallkeeper-day-board-plan.md`),
built on `feature/day-board` in an isolated worktree per the goal's
constraints. The LAW held throughout: event times exist only as Diary
bookings; the board is a pure projection of `GET /calendar` plus one shared
clock.

### What was built

- `packages/web/src/pages/hallkeeper/lib/day-board-state.ts` — the pure
  state machine. `deriveDayBoard(response, nowMs)` → per-room lanes of slots
  with state, tone, cadence and countdown label. States: scheduled →
  organisers-due (green, 4s pulse; keyed off the earliest matching setup
  *phase*, min'd with doors) → guests-due (amber, 3s) → imminent
  (deep-amber, 2s) → in-progress (claret LIVE breathe) → done (faded).
  Red + 1.5s pulse is reserved for exceptions; a blocking
  `insufficient_turnaround` conflict flags **both** slots of the pair, while
  warning severity rides as detail text and never escalates the state.
- `DayBoardPage.tsx` + `day-board.css` — Ink & Gilt board inside the app
  shell. Text is always paper-on-ink (AA); tone lives only in the dot,
  border and ring; the legend teaches every meaning in words. All pulses
  are transform/opacity keyframes phase-locked through one
  `--dayboard-epoch` custom property set once per mount (every cadence
  divides 60s). 30-second clock tick; `boardRange(nowMs)` re-derives across
  midnight so a wall tablet rolls to the new day on its own.
  `prefers-reduced-motion` computes every animation to `none` — the chip
  text already carries the full meaning.
- Route `/hallkeeper/today` (admin/staff/hallkeeper) + "Day Board" rail
  link in `DashboardLayout`.
- New harness `pnpm --filter @omnitwin/web visual-check:day-board`
  (`scripts/day-board-visual-check.mjs`) — own headless Chromium,
  route-mocked calendar built relative to `Date.now()` so every state is on
  screen whenever it runs, **two** browser contexts (`reducedMotion:
  no-preference` and `reduce`).

### Incidents and findings

- **Worktree api `.env` gap**: the clean worktree lacked the untracked
  `packages/api/.env`, so `/auth/me` had no Clerk secret and 403'd — the
  UI showed "signed in as planner", the same failure class as the Aug-31
  production access incident. Copying the env file and restarting the API
  fixed it. Lesson: T-518 stack in a fresh worktree needs *both* web and
  api untracked env files copied.
- **Pre-existing suite breakage (not this lane)**: twin
  `room-selector.test.ts` fails to load in any clean checkout because it
  reads gitignored `public/twin/trades-hall/manifest.json` (since
  b728a3a6). Inherited; flagged in the S1 PR.
- **Zod boundary bite**: the harness fixture initially omitted
  `CalendarConflictSchema.id`, and the client's response validation
  rejected the whole payload — a useful reminder that the web client
  *does* validate `GET /calendar` for real (the page unit tests mock above
  that boundary, so only the harness could catch this).
- **Chromium `innerText` applies `text-transform`** — assertions against
  uppercased state labels must be case-insensitive.

## When ribbon S2 shipped (T-557) — the plan's booking, draggable in the cockpit

Slice 2 on `feature/day-board-s2`. The LAW held: the ribbon is a projection of
GET /calendar; the only write is ONE `moveBooking` PATCH through the
idempotent command path (from /plan it rides REST with an Idempotency-Key —
same ledger as the ws channel).

### What was built

- `components/editor/cockpit/when-ribbon-model.ts` — pure model (26 tests):
  finds the plan's booking by scanning calendar entries for `?eventId` (no
  lookup endpoint exists; ±7-day window widened once to ±90), builds the
  day's ghosts (occupancy = booking ∪ its event's room phases, the server
  engine's own merge), hard exclusions (ink-vs-ink only — DB truth),
  guideline buffers sized by a client mirror of the engine's
  most-specific-wins rule resolution (pinned by tests), and the drag
  reducer: 15-min snap (1-min with Shift), clamp-with-overshoot against
  hard walls, soft buffer flags, min 15-min duration on resize.
- `WhenRibbon.tsx` + `when-ribbon.css` — a new `ribbon` grid row in the
  cockpit shell (no z-index needed; the stage's fixed chrome cannot reach a
  sibling grid row, so no avoidSelectors churn). The bar tracks the pointer
  1:1 (never gated behind reduced motion); snapping lives on a dashed
  landing shadow; release spring-settles via `lib/springs.ts`
  ({380,32} settle, {300,18} underdamped bounce off inked walls with
  asymptotic rubber give). Ink moves keep the confirm step (ink resists);
  pencils pass under inks with the warning, never a block; releasing inside
  a buffer commits WITH the guideline copy — the team judges. Optimistic
  override with compare-and-rollback; `INK_SLOT_TAKEN`/`BOOKING_STATE_CHANGED`
  → snap back + refetch + slot-taken copy; Undo = compensating PATCH
  (never the planner's scene history). Keyboard: arrows/Shift/Alt/Enter/
  Escape, aria-live announcements, no animation on keyboard commits.
  Read-only strip for non-staff; "not in the Diary yet" empty state links
  to /diary (no direct createBooking — hold hygiene cannot be honestly
  invented). Copy-as-data + claim guard (5 tests).
- **API addition (flagged divergence from the plan's "web-only" S2 label —
  the goal's own feature list requires buffer geometry)**: `GET /calendar`
  now carries the venue's `turnaroundRules` — the SAME rows the conflict
  engine resolves, optional on `CalendarResponseSchema` so older
  servers/fixtures stay valid. No DB migration. Local API serves it (tsx
  watch); PRODUCTION API DEPLOY REMAINS BLAKE'S `railway up` — until then
  the deployed ribbon simply draws no buffers.
- New harness `visual-check:when-ribbon` (12/12): renders inside the real
  cockpit, real pointer drag (1:1 transform + shadow proven mid-drag),
  ink-resists confirm on release, and the confirmed commit captured on the
  wire: exactly one PATCH with startsAt+endsAt and an Idempotency-Key.
