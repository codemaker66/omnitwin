### What was built

- `packages/web/src/pages/hallkeeper/lib/day-board-state.ts` — the pure
  state machine. `deriveDayBoard(response, nowMs)` → per-room lanes of slots
  with state, tone, cadence and countdown label. States: scheduled →
  organisers-due (green, 4s pulse; keyed off the earliest matching setup
  *phase*, min'd with doors) → guests-due (amber, 3s) → imminent
  (deep-amber, 2s) → in-progress (claret LIVE breathe) → done (faded).
  Red + 1.5s pulse is reserved for exceptions; a blocking
  `insufficient_turnaround` conflict flags **both** slots of the pair, while
  warning severity rides as detail text and never escalates the state.
- `DayBoardPage.tsx` + `day-board.css` — Ink & Gilt board inside the app
  shell. Text is always paper-on-ink (AA); tone lives only in the dot,
  border and ring; the legend teaches every meaning in words. All pulses
  are transform/opacity keyframes phase-locked through one
  `--dayboard-epoch` custom property set once per mount (every cadence
  divides 60s). 30-second clock tick; `boardRange(nowMs)` re-derives across
  midnight so a wall tablet rolls to the new day on its own.
  `prefers-reduced-motion` computes every animation to `none` — the chip
  text already carries the full meaning.
- Route `/hallkeeper/today` (admin/staff/hallkeeper) + "Day Board" rail
  link in `DashboardLayout`.
- New harness `pnpm --filter @omnitwin/web visual-check:day-board`
  (`scripts/day-board-visual-check.mjs`) — own headless Chromium,
  route-mocked calendar built relative to `Date.now()` so every state is on
  screen whenever it runs, **two** browser contexts (`reducedMotion:
  no-preference` and `reduce`).
