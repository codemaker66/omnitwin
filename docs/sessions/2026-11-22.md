# 22 November 2026

## The spine, stage 1, part one (T-704): built and reviewed, in review as #436

The [design](../superpowers/specs/2026-11-13-the-spine-design.md) merged as #427 and the
[plan for stage 1](../superpowers/plans/2026-11-14-the-spine-links.md) as #433. Part one of stage 1 is #436.
It is built and reviewed, and it waits for a database merge slot.

**What was built.** A proposal, a deal and an enquiry each gain a link to their event, pinned to the event's
venue. A link can be moved but never emptied, and an event holds at most one open deal. One step in the
database joins old records to their events without a guess. What it cannot place goes on a list of joins for a
person, and every join it makes is recorded, so a written undo can take it back. A read-only count of nine
numbers finds each record that should have an event and has none, or whose links disagree. The bind now joins
an enquiry's own event first and keeps the enquiry's link in step. A new deposit request takes its proposal's
event. The join and the count run every night, and by hand, in a workflow of their own. The links stay
nullable; a later stage makes them compulsory once production reads zero.

**How.** Eight tasks, each built test-first by one builder and reviewed by another. Then one review of the
whole branch: no critical finding, two important ones, both fixed. Then one pass of fixes, and one re-check of
the fixes, which left nothing critical or important.

**Decisions made during the build.** The design and the plan carry dated amendments for them.

1. The plan's Task 11 moved from part two into part one: a deposit request takes its proposal's event, under
   the proposal's lock. Without it, a request made after its proposal was joined would never get an event, and
   the count could not reach zero.
2. There is no check after each release, and the nightly check is a workflow of its own
   (`.github/workflows/event-rules.yml`), not a job beside the clean-up. The host releases on its own clock, so
   a job in the deploy workflow could not run after the release. This changes one call the design listed for
   the founder to check (its section 13).
3. Run by hand, the nightly check only reads unless asked to join, and it runs only from master. A join by hand
   against production is the founder's call.
4. Only live bookings (active and not deleted) keep an enquiry's link in place when a booking is moved. The
   plan's word was "undeleted".
5. A deposit request in force is counted in its own right, whatever became of its proposal.
6. The bind writes an enquiry's link only when nothing else of the enquiry's own (its bookings, deals,
   proposals or floor plan) reaches a different live event. Otherwise the link is left, and the nightly join
   lists the enquiry for a person. The booking itself is bound as before.
7. A suite whose helper migrates the database it is pointed at is never run from a branch with an unmerged
   migration against a shared test database. CI is its bench.
8. Comments name the migration `*_event_spine_links`, without its number. The number is fixed at the merge
   slot.

The design's section 5.4 also gains the full lock order, combined with the Diary's (its section 6.2), with
where the code keeps each rule. The place of a person's row against an import batch's row is left to be
settled with the Diary's build.
