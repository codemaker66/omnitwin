## Railway settings from GitHub, on Blake's approval (T-751): design approved

After the move, a settings change still needed one computer with a signed-in
tool. Blake decided that changes should instead be applied from GitHub,
with a stored Railway token behind his own approval there.
[The design](../superpowers/specs/2026-11-22-railway-settings-apply-from-ci-design.md)
was approved by Blake the same day. Nothing is built yet.

### What the design says

- The token sits in a protected GitHub environment that releases it only after
  an approval, and only to a run on `master`.
- A first step with no token shows what changed. A second, approved, shows
  Railway's plan. A third, approved, applies exactly those lines, checks that
  nothing is left, and waits for Railway's report of the new deployment.
- From GitHub, only updates to one service's build and deploy settings.
  Anything removed, emptied or added stays by hand.

### Decisions made, with reasons

- **The first draft was checked before it went to Blake.** A reviewer
  read each fact against GitHub's and Railway's own pages and looked for ways
  round the design's anti-goals. It found that the first approval gave the
  token to the commit's code before anything was shown, that three stated
  facts were wrong or out of date, and that the redeploy's success could not
  be read from the public probes. The design's section 13 lists each and
  what changed.
- **Railway's ready-made action was not used.** It plans on every pull request,
  so it needs the token as a repository secret, which any branch's workflow can
  read, and it runs each branch's own settings file beside that token.
- **The design says what it does not protect against.** An approval trusts the
  commit, and an approval is as strong as the sign-in that gives it.
- **The release lead's review tightened the text before any code.** It found no
  way to the token without an approval, and had nine points closed in words;
  the design's section 14 lists them. The row's number also changed, to T-751.

### What this entry does not claim

- Nothing is built, and no token exists.
- Several things the design leans on are not yet proven; it lists them, and the
  build proves each before anything relies on it.
- Blake chose to build it now, with automated tools held by a rule and
  not by GitHub, and to keep two approvals. The design records both choices.
