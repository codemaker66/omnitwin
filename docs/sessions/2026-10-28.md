### Decisions
- supplier-requests-5: a per-venue advisory lock over the auditor's two options. It is exact, which an overlap
  re-read window is not, and needs no migration or new cursor meaning, which an `xid8` horizon does. A venue's
  message writes wait for each other for one send's transaction.
- supplier-requests-4: the whole venue team, not only the pass's creator: any manager can answer a supplier.
- supplier-requests-2: re-arm on reopen rather than removing reopen from the client branch. No web control reopens
  a request today, but the API allows it from staff and the linked client.
- admin-venues-3: a restore route rather than a partial unique index: no migration on the release path (open PRs
  already collide on 0103), and a mistaken delete comes back with its layouts and history.
- admin-venues-6: relabel, record-only. Nothing reads `accessEnforced` or the review state.

### Review (ran at max effort)
The `deep-reviewer` agent reviewed #289, #299 and #302 adversarially at max effort. It reported six findings, each
reproduced on the disposable database; each was checked here against the code before it was fixed, and each fix has
cases that fail on the old code:
- #302: the writers read the room unlocked and outside their transactions, so a booking, an enquiry's hold, a viewing,
  a proposed time or a timed phase written as the room was deleted landed in it, hidden from the Diary. A change of
  times, or a called-off booking put back, could fill a room already deleted, with no race at all. Every such write
  now calls `lockLiveRoom` first (`d7e6109a`, 10 new cases; two source-text pins moved to the new code).
- #302: phases of lost or cancelled events blocked a delete that the Diary gave nobody a way to clear. They no longer count.
- #289: a publish read its people unlocked, so a check cleared mid-publish was published over and the person told.
  Read `FOR SHARE` now (`309f7a7b`).
- #299: the client's snapshot read threads, then messages; a thread opened between the two held a message the cursor
  passed for good. One statement now (`b34b0791`).
- #299: the cursor test passed with the lock moved below the insert, and its probe counted other sessions' waits. A
  case where a send stalls after drawing its cursor now catches that variant, and the probe counts only its own sessions.
- #299 with #260: the merge resolution this log first gave (venue lock first) deadlocks; corrected above.
