## 14:55 — T-647: the live BPF v2 listing lacks the v1 ids; collections are now chosen from it

- **Live state.** #53 (`ae05f917`) is deployed. The Trades Hall sky answered 200 with October normals and `degraded.reason: "upstream_unavailable"`. Railway logged at 13:19Z: `venue_sky_upstream_failed`, stage `collections`, status 200, detail "percentile collection not offered". So Blake's `MET_OFFICE_BPF_API_KEY` is set and accepted, but the listing did not contain the id the code required.
- **Cause.** The code required `improver-percentiles-spot-uk` or an id ending in it. That is a v1 id: the Met Office's own utilities (weather_datahub_utilities/bpf_download) were written for the v1 path and list the four `improver-…-spot-{uk,global}` ids, and the glossary calls the models `mo-improver-…`. The v2 OpenAPI documents a collection as `{ id, title, links, output_formats }` and names none. A third-party v2 client lists `uk-spot-percentiles`, `uk-spot-probabilities`, `global-spot-percentiles` and `global-spot-probabilities`, each with one instance, `blended`. No live body was read here.
- **Change** (branch `claude/t647-bpf-collections`):
  - `bpf-collections.ts` classifies each listed collection by the EDR `parameter_names` it declares, otherwise by the words of its id and then its title.
  - It prefers the UK set, falls back to the global set, and takes probabilities from the percentiles' region.
  - It never chooses an unclassifiable collection, or a percentile set without total cloud or temperature.
  - Each listing is logged with its ids, titles and parameter counts (`venue_sky_collections_selected` / `_unmatched`).
  - An unmatched listing is held for 6 h. Before, every 30-minute retry spent a collections call, 48 a day, which would have tripped the 40-call cap and then reported `forecast_quota_exhausted`.
  - The forecast `source` now names the probability collection actually read.
- **Not done here.** No Met Office call with any key. The live proof is the deployed endpoint and the `venue_sky_collections_*` log after this deploys.
