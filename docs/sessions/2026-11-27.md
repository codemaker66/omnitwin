# 27 November 2026

## The job list: the review's fix round (T-702, stage 1)

- The pull request's full review found no blocker and asked for fifteen small fixes in one push. They are in, one
  commit for each part (the migration, the worker's state, Sentry, the admin routes with the page, the tests, these
  words). Every new test, and every test whose assertion changed, was watched failing with its guard removed.
- **The migration** (still 0110; the journal is untouched). It now takes the locks its keys need on `venues`,
  `events` and `enquiries` before it touches `email_sends`, so no wait for another table's lock happens while email
  traffic is held. The venue index on `email_sends` is partial, and the event and enquiry links each have a partial
  index, so removing an event or an enquiry checks its sends by index.
- **The worker.** Putting claims back is one statement fed by `FOR UPDATE SKIP LOCKED`: a handler's `completeIn`
  transaction left open past its claim no longer stops every server's recovery, and with it the whole pass. A
  recovery that fails is a fault, but the claims after it still run. Every call of the worker's own runs in a
  transaction of its own whose `SET LOCAL` statement and lock timeouts let the server end it at the worker's limit;
  nothing is set for a whole session, which a transaction-mode pooler would not keep. A claim that has run out and
  still stands is planned a minute ahead, so a held row does not wake every server four times a second. The
  regression tests run on a pool with no server-side timeouts, as production's pool has none, with the row held by
  a second real session.
- **Sentry.** The scope helper's comment now says what it clears (the isolation scope only) and that it differs from
  the escalation scheduler's helper; the T-765 row says what folding the two must choose. A new case starts the
  server's own worker through `startJobs`, with the worker on and a stand-in DSN, so the wiring is tested.
- **Stuck work.** A refused Try again or Close says what became of the job: someone has already closed it, it has
  already run, or it is already back on the list. The page counts "last ran" on the server's own clock and says
  when the list was read; shows the list being read again after an error; says the self-test's verdict truthfully;
  has one polite live region for verdicts and outcomes; describes each row's buttons by their row; and says what
  Try again and Close do before they are pressed (the note form's button is now "Close the job").
- **Tests.** The retry ladder is pinned to its stated values, with a case for a job allowed eight tries. The page's
  two double-press tests press twice inside one act. In Chromium 156 a focused button that becomes disabled loses
  focus to the page's body (measured in a browser), so the one focus test that assumed it keeps focus was removed,
  and the refused-Close focus test now starts from focus lost.
- **The note** (`docs/engineering/the-job-list.md`) now covers switching the worker on, the way back, what is not
  yet proved, what the next stage must settle first, and the `email_sends` half of the migration with its status
  rule.
- **A correction to the 26 November entry.** The job list's scope helper is not "of the same behaviour" as the
  escalation scheduler's: the job list's clears the forked isolation scope, the escalation scheduler's clears only
  its breadcrumbs.
- Not done here: the pull request's description is corrected outside the repository; CI has not run on this head,
  and no typecheck was run in this round.
