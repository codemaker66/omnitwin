## 00:30 — Event-spine Phase A, the bind (migration 0090)

- **What changed.** Every hold and ink is written with its event in the booking's own transaction:
  the Enquiries desk's "Hold the date" (it was written with `eventId: null`), the Diary's create, edit and
  transitions, the client's proposed window, and the seed. Rows written straight into the table (the seed,

  enquiry or by a named event of the same venue, never by date and name. `bookings_bound_to_event` refuses a
  hold or ink without an event; both foreign keys to `events` are now `ON DELETE RESTRICT`.
- **Status follows the bookings.** `deriveEventStatus` (types): a live confirmed booking makes the event
  `confirmed` (later steps people recorded are kept); live options leave it `draft` (or `proposed`); every
  option gone closes it as `lost` (new status); a cancelled confirmed booking leaves it `cancelled`. Every
  booking write re-derives it; `PATCH /events/:id` refuses a status the Diary would contradict. A released
  competing option's event is `lost` at once, and the Diary calendar stops painting its phases.
- **"Start a floor plan" is gone.** The drawer's Floor plan section opens the booking's event directly

  the roles the planner admits (admin, manager, staff, planner), since it writes nothing. The Day Board no
  longer asks anyone to link an event; a house block reads "A house block has no setup sheet."
- **Migration 0090** backfills before it constrains, in one transaction with a five-second lock limit:
  joins each unbound hold or ink to its enquiry's event or makes one per group, derives every event's status,
  and writes `event_binding_reviews` (an enquiry already split across events; a new event that may be the
  same occasion as another booking's; every existing event whose status changed, with the status it had).
  Nothing is deleted; re-running changes nothing.

## 02:00 — The bind, independent verification

The verifying engineer's pass over the branch (heavy checks run one at a time, `TZ=UTC`).

- **Defect found and fixed: a deadlock between writers of one event.** `syncEventStatus` locked the event
  `FOR UPDATE`, but every booking written or moved onto an event holds `FOR KEY SHARE` on it through the
  foreign key, and the two conflict. Two coordinators adding rooms to one event at the same moment, or two
  bookings moved between two events in opposite directions, each held a key share and waited for the other's:
  Postgres aborted one write with `40P01 deadlock detected` (a server error for that coordinator). Reproduced
  by two new tests in `booking-event-bind-postgres.test.ts` (a third session holds the event `FOR NO KEY UPDATE`,
  which lets both foreign-key checks through), both failing on the old lock. The sync now locks
  `FOR NO KEY UPDATE`, which still serialises the syncs with each other and with `PATCH /events`; both tests pass.
