## 02:00 — The bind, independent verification

The verifying engineer's pass over the branch (heavy checks run one at a time, `TZ=UTC`).

- **Defect found and fixed: a deadlock between writers of one event.** `syncEventStatus` locked the event
  `FOR UPDATE`, but every booking written or moved onto an event holds `FOR KEY SHARE` on it through the
  foreign key, and the two conflict. Two coordinators adding rooms to one event at the same moment, or two
  bookings moved between two events in opposite directions, each held a key share and waited for the other's:
  Postgres aborted one write with `40P01 deadlock detected` (a server error for that coordinator). Reproduced
  by two new tests in `booking-event-bind-postgres.test.ts` (a third session holds the event `FOR NO KEY UPDATE`,
  which lets both foreign-key checks through), both failing on the old lock. The sync now locks
  `FOR NO KEY UPDATE`, which still serialises the syncs with each other and with `PATCH /events`; both tests pass.

## 21:00 — Live co-editing v1 (T-664)

Blake chose to build live co-editing now ("build version 1 now", through Session orchestration). Built on
`claude/live-coedit-v1` from the 22 August design (its phases 2 and 3), on the existing
`/ws/configurations/:configId` socket. [Engineering note](../engineering/live-coediting.md).

- **Decisions.** Live ops travel as whole-object state in real metres and are drawn as an overlay that never
  enters the saved document; last write wins per object in the hub's per-room sequence; a later peer write on
  an object this person changed YIELDS it (local returns to the server copy until edited again); a commit
  refetches and adopts or rebases object by object; while live a 409 rebases and retries once. Access is the
  owner and the venue floor; clients get nothing new. Autosave runs at 400 ms while someone else is present.
- **Review fixes (independent security review).** A deeply nested metadata frame crashed the hub's
  `JSON.stringify` outside its try, which would have taken the API down (reproduced by test, fixed in three
  layers); access is now re-checked every 20 s heartbeat (`live.revoked`); owner clause is an allowlist;
  websocket `maxPayload` 1 MiB; slow members skip frames. Found while testing: echoes paired by send order
  broke when the hub dropped a frame; now paired by object id with a 2 s claim expiry.
- **Evidence (local).** API: ws suites 65 tests including two real sockets on the real route against a
  database stub that throws on any write. Web: full suite 644 files / 8,905 tests before the hardening
  commits; live-layer suites 36 + editor-store live 11 after. Two-browser e2e on a disposable Postgres
  (127.0.0.1:55407, data on E:), API in test mode on 3027 and Vite on 5197: 8/8; action → other browser's
  scene 1–3 ms after warm-up; gesture end → clean editor 436 ms (1.4–2.8 s while a headless browser rendered

- **Gaps recorded.** Single-object REST routes do not advance the revision and announce nothing (the planner
