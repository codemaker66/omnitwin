## 14:00 — Supplier passes round 2 (PR #106): supplier confirmations kept by the database

Branch `claude/doors-20261016`, worktree `E:/claude/build-20261016/doors`, `origin/master` merged in first (clean merge).

- **Decision (Blake): "supplier confirmations kept".** Migration `0092_supplier_records_kept` (number provisional until merge) changes `supplier_acknowledgements.pack_id` and `supplier_coordination_packs.handoff_pack_id` from `ON DELETE CASCADE` to `ON DELETE RESTRICT`. A delete of a replied pass, of the handoff pack a pass was issued from, or of the configuration or snapshot that pack cascades from is now refused as a whole statement. The migration finds the keys by table, column and referenced table, so a differently named key is also replaced. Reapplying it is harmless. The Drizzle schema states the same.
- **Why RESTRICT and not SET NULL.** No code path deletes a pass, a handoff pack, a snapshot a handoff pack refers to, or a configuration one was compiled from. The one hard delete of configurations is preview cleanup, which already skips those. Snapshot pruning keeps them. Passes are withdrawn, never deleted. A pass already carries its own `venue_id` and `event_id`, so nothing would need copying.
