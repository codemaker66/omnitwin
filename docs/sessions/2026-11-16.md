### The tools pull request's review ([#442](https://github.com/codemaker66/omnitwin/pull/442))

The release lead confirmed that the six seams default to the hall's old values, that holding BLAS to one thread covers every threaded entry point, and that the proof logs show what the pull request claims. It asked for four things, all done:

- The T-662 row no longer names a folder on the build machine.
- **A config that is not well-formed is refused by name.** The driver built its `Room` from the config before checking it, so a missing block or an unknown wall id ended in a Python traceback. It now runs the checker first, in every mode, and refuses in the checker's words before the work folder is made; a file that is missing, not UTF-8 or not JSON is named as that. The same order catches a config without `survey.publish` or `survey.outputs` before the refusals that guard a publish read them. Reproduced first (eight variants, eight tracebacks), then covered by tests.
- The tools' README now says exactly what was computed again after gate B24 (the 12 corner files, twice) and what stands from that morning (the end wall's other 11 files), and no longer lists the end wall's canvas and 2 mm image as unproved.
- **CI runs the tools' static, unit and gate tests** in a job of their own, whenever a change touches `tools/surveyed-rooms` or `tools/grand-hall-survey`.
