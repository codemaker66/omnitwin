the fix: 33 fail on master (the 3 that pass pin unchanged conflict

Measured in Chromium on master: a move followed by the slate's room switch to

**What changed (both chromes, in the shared save layer).**
- Hiding the page sends unsaved work at once, as a keepalive request when the
  body is at most 60,000 bytes; `pagehide` does the same if the hide did not;
  the route unmounting flushes the waiting autosave instead of cancelling it
  (the F26 timer cleanup was the drop). `beforeunload` asks only for unsaved
  work this device does not keep.
- Work kept on this device restores as one undo step with a receipt:
  "Restored 3 changes you made at 21:41 on this device · Saving", then
  "Saved 21:42" (yesterday and older days are named).
- D-X2: a kept copy the server already holds (a close-time save that landed
  unheard) opens clean, with no conflict; compared at the database's precision,
  pieces placed since paired by content.
- D-X3: `loadConfiguration` gives the outgoing layout's work up to 2 s
  (`saveBeforeLayoutChange`), a save already in flight first; the slate awaits
  the same call before a room or layout switch, saying "Saving · N changes".
  What does not arrive stays here, and the next layout says "Your changes to
  the Grand Hall layout are kept on this device and save when you open it
  again." Work this device cannot keep holds the switch (Try again, or open
  without them). The room switch now opens the room: it names the layout it
  leaves in the navigation state and the page closes exactly that one.
