- **1. Staff-only enquiry files (P0), #263.**
  - **Defect:** `GET /uploads/enquiry/:id`, the only place an enquiry's files are listed, returned every file on
    the enquiry to its client owner. That included the venue's own uploads, each with a signed read link.
  - **Fix:** a reader who reaches an enquiry as its customer now lists only the files they uploaded. The `files`
    table has no audience column and nothing in the product shares a staff upload with a client, so staff uploads
    stay with the venue. Sharing one on purpose would need an audience flag, a product decision.
  - **Evidence:** `enquiry-files-postgres.test.ts` drives the real routes. It failed on master; CI was green on
    the PR.
- **2. Recipient addresses in the API email logs, #264.**
  - **Defect:** all 11 log records in `services/email.ts` carried `recipient`.
  - **Fix:** they now carry the event and `idempotencyKey`, which finds the `email_sends` row. Provider error
    text has addresses replaced.
  - **Evidence:** a test runs every send path through the production logger config. Six tests failed on master;
    CI was green on the PR.
- **3a. Sentry privacy, code part, #271.**
  - **web-auth-routing-4 (confirmed):** share tokens, view-only and supplier tokens, legacy share codes and guest
    layout ids are now templated to `:token` in browser events and breadcrumbs. The rule lives in
    `@omnitwin/types` `capability-paths` and covers `/configurations/<uuid>`, `/hallkeeper/<uuid>` and
    `/blueprint/<uuid>`.
  - **API, the same templating:** in the request log, events, breadcrumbs and transactions.
  - **One capture path:** the SDK's Fastify integration also captured thrown errors (4xx included, and each 5xx
    first, so the stored events lacked route tags). It now captures nothing; the error normaliser's hook is the
    one path. The hook no longer attaches `request.ip`.
  - **Adversarial review findings, fixed:**
    - transactions carried the visitor's IP (`http.client_ip` from X-Forwarded-For) and the request body;
    - spans kept the query in `url.path`;
    - matching was case-sensitive.
  - **Evidence:** an end-to-end test runs the real SDK against a loopback ingest. It failed on master three ways.
