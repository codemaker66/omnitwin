### Decisions made, with reasons

- **The shaped-room branch is not split.** The fallback recorded on 11 November was to ship placement without the floor-aware gangway review. That would be worse than the branch as it is: with pieces rightly allowed into the alcoves, master's review, which measures to the centred rectangle, would call every alcove placement beyond a wall.
- **The branch's judges are fixed before its code.** `verdictOn` judged only items at 0.00 m, and `judge` took a straight-line gap, so neither could see a width measured through a wall. The fifth round's brief has them taught first and proved able to fail on the unfixed code.
- **A reply field the web requires must be one the deployed API already sends, or have a default.** #400's web read `created` as required while master's API sends none; the web and the API deploy separately. It now defaults to what the older API did (7ebc21b8), as `api/crm.ts` and `api/proposals.ts` already do.
- **Small helpers that public bundles need live in modules that import nothing.** #404 first took `isCalendarDate` from `event-brief-draft.ts`, which pulled the Event Architect modules into every bundle carrying the public enquiry schema: 32,156 to 99,475 bytes before minifying, 6 modules to 17, measured by bundling the built module alone with rollup. It moved to `packages/types/src/calendar-date.ts`, and `enquiry-module-imports.test.ts` holds the enquiry module to its seven imports. The bundle budget tests read a built `dist` and skip locally, so they would not have said so before CI.
- **"Never the enquiry's email" is enforced in the bind.** #407's first version kept the email out of an event's name only for an enquiry with a blank name, the shape of older rows; today the public route files a guest who gives no name under their email. The fixture had been written to the fixer's model of the data, not to what the route stores. The rule now sits in `bindBookingToEvent`, which already reads the enquiry row.
