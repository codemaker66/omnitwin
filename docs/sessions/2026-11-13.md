### The review round (afternoon)

The release lead's review of 072bf704 held three majors and nine minors. One new head answers all of them, on master
85a17749 (merged as 6300897c; one conflict, the 12 November log, where both sides appended a section).

- **A claimed draft's answer is written at once (R1).** A signed-in person's new plan is created as a guest's draft
  and claimed straight away, so its answer was kept only on the device until the next signed-in open, and another
  device or the coordinator saw no event. `layoutClaimedEventKind` now runs beside both places that make a draft the
  person's.
- **Only a layout new as it opened is asked (R2, P1).** The rule read the floor live, so emptying a never-answered
  layout (select all and Delete, the last table, a co-editor, a reload of an empty copy) opened the question over
  the work and swallowed Ctrl+Z. The load now latches whether the floor was empty in both the opened copy and the
  server's; a reload can clear the latch but never set it, and the picker clears it for good once anything stands
  on the floor. Answering the question is not what ends it: work is.
- **The picker is mounted beside the 3D and 2D views (P2, T1).** It was mounted inside the cockpit, which exists only
  in 3D, so the phone's event name did nothing in the 2D plan and the change opened unasked on the way back. It now

  seen written, whichever layout is open, and only the newest settles it (a same-kind answer written earlier cannot
  clear a later one). 401, 408, 429, the route's own 409 `RETRY`, server errors and no network are tried again after
  2, 5, 15, 30 and 60 seconds and on coming back online; 400, 403, 404 and 409 `CONFIG_LOCKED` are final.
