# Session log — 2026-08-15

## The question

Blake asked which output varieties to select when exporting PortalCam Gaussian
splats from LCC Studio. The answer turned out to be already written across the
repo's evidence layer, and the operator-facing document that should have carried
it was contradicting it.

## The answer given

Take the whole export set — it is cheap, and the rebuild is not. But the option
that actually decides quality is not on the format list: it is the
reconstruction profile.

- **Build at SH degree 3.** SH0 (labelled *Mobile* / *Portable* in our records)
  discards all view-dependent colour, which is the precise property the splat
  layer exists to carry under D-005a. SH3 decimates to SH0 at any later date;
  SH0 never promotes back without rebuilding from the capture.
- **Codec choice barely matters.** From
  `docs/reports/reception-room-hd-root-investigation.md`: PLY master → valid
  leaf frontier measures 41.4–43.8 dB PSNR / 0.958–0.972 SSIM across both SOG
  and SPZ, and same-source SOG vs SPZ measures 42.0–44.0 dB. Effectively free.
- **The LOD hierarchy is what actually costs quality.** Mounting all LCC2 levels
  simultaneously instead of the leaf frontier measures 27.7–30.2 dB with visibly
  doubled edges — a 12–14 dB fault, silent, and the largest in our estate.
  Reception Room rendered 3,455,732 Gaussians where its valid four-member
  frontier holds 1,978,258.
- **The trajectory sidecars are the irreplaceable ones.** Raw frames sit inside
  the proprietary `.xbin` (XBAG) container and calibration inside an encrypted
  `lixel.zip`, with no authorized open path established. `poses.json` (~5 Hz)
  and `poses.csv` (~10 Hz) are the only capture-side geometry that survives that
  wall. They are kilobytes. They were not in the runbook at all.

## T-540 — runbook correction (done)

instructions dated 2026-06-15, months before the Reception Room forensics. It
told the operator to export one "raw" PLY, one "processed" PLY, a preview and a

**Seven rooms remain unprocessed.** An operator following the document as
written would have built at whatever profile the dialog defaulted to and lost
the trajectories permanently.

Rewritten: an "Export Profile" section pinning SH3 and the leaf-frontier rule
with the measured deltas above; a ten-row export checklist; LCC2
directory-naming rules (chunk names are manifest-referenced — renaming breaks
the hierarchy); the LCC/LCC2 non-OSI rights constraint from the corrections
report §2; a new `master/` R2 prefix separating the unquantized lineage root
from served runtime variants; registration examples that register the master
`staged` and each leaf-frontier chunk `usable`; five new safety rules.

Doc-only. No code touched, no room reprocessed, and no claim that any existing
asset improved.

## Schema gap found — T-541 (not-started)

`poses.csv` **cannot currently be registered**. `.csv` is absent from
`RUNTIME_FILE_EXTENSIONS` (`packages/types/src/asset-version.ts:115`), so
`assetKindAllowsExtension` rejects it at the register-version boundary. The
runbook now documents a zip-as-`other` workaround, which preserves the bytes but
loses the artifact's type identity. T-541 raised to extend the whitelist.
