## T-736: the sheet check's no-signal test

- The cause was a lost event, not a slow page. SheetCheckPage attached its `online` listener in a passive effect, which React 18 runs as a separate scheduler task after the commit; under load, Testing Library's `findBy` could return and the test dispatch `online` in between. A probe caught it: one dispatch 0.2 ms before `addEventListener`, 1 in 100 replays under 10 busy loops.
- The listener now attaches in the commit (`useLayoutEffect`), before anything can see "Can't check: no signal." A new test forces the scheduler to yield at every check: it fails on the old code every time (6 of 6) and passes on the new. A second test pins one retry per returning signal.
- Repeated file runs under CPU load could not tell old from new (30 of 30 and 29 of 29 passed), because the window is microseconds wide; the forced-yield test is the proof. The same pattern (a listener attached by a passive effect right after the render that turns it on) is in HallkeeperPage (twice), RequestsProvider and use-slot-observations; no test triggers it today.
