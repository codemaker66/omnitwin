**Lessons kept.**

- A rule about what a photograph shows is judged on photographs. A synthetic wall proves geometry (which texels
  are seen, which are clear); it cannot say which of two views looks right, because its pictures have one exposure
  and exact poses.
- Two builds are compared as pairs, not as two rates: how many of the same texels turned worse, turned better and
  stayed, counted by patch as well as by texel, beside the same count on texels neither build moved.
- Code that counts evidence is read by someone else before its figures are quoted. The first version of the paired
  counts cut a patch in two wherever a texel was left out of the count, which makes chance look like proof, and
  judged its control more kindly than the texels it was a control for. A reviewer found both before the pull
  request was opened, and every figure quoted now has a saved script and result behind it.
- A forecast is written to a file before the build, and the build is checked against the file. A test of one class
  of texels is stated, with its unit and its direction, before the build exists.
- A count that seems to corroborate a finding is checked for being the same evidence counted again.
- A verdict sent between sessions can be lost at an account switch: #452's sat undelivered for a day. After any
  switch, ask the reviewer for the state of every open pull request.
- Before a branch's long checks, test that it still merges with master and whether master's lockfile or shared
  types moved.
- A patch's feathered seam must lie on patched content or on content like it: where the original is unlike (an open
  doorway beside dark wood), run the patch on under its neighbour.

## T-736: the sheet check's no-signal test

- The cause was a lost event, not a slow page. SheetCheckPage attached its `online` listener in a passive effect, which React 18 runs as a separate scheduler task after the commit; under load, Testing Library's `findBy` could return and the test dispatch `online` in between. A probe caught it: one dispatch 0.2 ms before `addEventListener`, 1 in 100 replays under 10 busy loops.
- The listener now attaches in the commit (`useLayoutEffect`), before anything can see "Can't check: no signal." A new test forces the scheduler to yield at every check: it fails on the old code every time (6 of 6) and passes on the new. A second test pins one retry per returning signal.
- Repeated file runs under CPU load could not tell old from new (30 of 30 and 29 of 29 passed), because the window is microseconds wide; the forced-yield test is the proof. The same pattern (a listener attached by a passive effect right after the render that turns it on) is in HallkeeperPage (twice), RequestsProvider and use-slot-observations; no test triggers it today.
