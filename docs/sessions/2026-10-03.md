## T-635 — Proposal templates (X1; Tier B #16)

A booker keeps a proposal's message and quote lines as a template for a room
and an occasion, and starts the next proposal from it instead of typing it
again. A template holds no price: a price-list line is a reference priced from
the venue's list as it stands each time it is used (a price a head takes that
event's guests), and a typed line keeps its words and quantity and asks for its
price. Over words already written it asks Replace (the words kept to copy
beside a new composer) or Add its lines (only what is not already quoted).
Save as template fills its name, room and occasion from the event, never over a
field already typed in.

Shipped to master as `b0c510ec` (the feature, on migration 0085 from
`f51af168`), `ffdc2e09` (template work held both ways), `8847302d` (each hold
pinned by a test), `acc6c62a` (the two browser cases admitted to the gate,
inventory 379) and `82c82386` (Save as template's button kept while it has
focus). Five max-effort review rounds ran before the push; each confirmed
finding was fixed with a test seen to fail without its fix.

Known limits, recorded rather than claimed covered: an answer on its way when
the booker leaves the proposal, or when the composer closes under it (the
proposal sent from elsewhere), is not said, as with replies, links and
withdrawals on this desk; a removal's Undo is then reachable only by removing
and bringing back again from the list.

CI on `82c82386` (run 37151201856) failed on two jobs, neither from this
change: the Security Audit (a new advisory, below) and the browser gate,
which refuses any retried case and saw the planner case
`public-config-flow.spec.ts:497` ("Plan navigation and capacity controls clear
the event schedule and command deck") fail once and pass on retry. Deploy was
skipped.

It is live on `daa69ca7`, with the dependency fix below: CI 37172290118 and
Deploy 37173009652 passed (the browser gate ran both template cases, and the
planner case passed first time), and receipt 37173246881 found the API running
it. Without sign-in, `/venues/:venueId/proposal-templates`,
`/proposals/:id/event` and `/proposals/desk` refuse (401); the dashboard and
the client proposal page are served; the production browser pass passed.

## Dependency upgrade: typescript-eslint 8.22.0 → 8.48.0

- **Reason:** GHSA-vfj7-8cjw-p6xm (published 3 October), braces `<=3.0.3`,
  high, no patched release. Master's only path was typescript-eslint 8.22.0 →
  `@typescript-eslint/typescript-estree` → fast-glob 3.3.3 → micromatch 4.0.8 →
  braces 3.0.3, development-only.
- **Why 8.48.0:** the first release whose typescript-estree globs with
  tinyglobby (8.47.0 still uses fast-glob), so the smallest jump that removes
  the path. fast-glob, micromatch, braces and their own dependencies leave the
  lockfile; ignore 7.0.12 and tinyglobby arrive; eslint 9.19.0 and TypeScript
  5.7.3 are unchanged and satisfy the peer ranges.
- **What changed in lint:** strict-type-checked adds
  `no-unnecessary-type-conversion`; `no-unnecessary-condition` now checks
  optional chains on indexed access under `noUncheckedIndexedAccess`; and
  `await-thenable`, `no-redundant-type-constituents` and others gained report
  types. That surfaced 31 findings in existing code (types 2, foundry 6, api 9,
  web 14 plus one unused directive), fixed at the cause with no rule turned off:
  redundant conversions and optional chains removed where the value is already
  parsed or narrowed; the Foundry execution validators keep their runtime
  coercion explicitly (`String(x as unknown)`); redundant intersection members
  and single-use type parameters removed. Each package's diff was read by a
  sceptic for behaviour change; none was found.
- **Verification** (all run after the last source edit, on 4 October,
  local; CI follows): `pnpm audit --audit-level=moderate` finds no known
  vulnerabilities; `pnpm -r lint` and `pnpm -r typecheck` clean in every
  package; types 2,323 tests, reconstruction-foundry 598, the default API
  suite 3,641 on disposable PostgreSQL and its platform-database tests 189,
  the web tests around every touched file 337; API and web production builds
  pass.
