# 24 September 2026

## T-629 — application performance review

Blake asked to look at increasing performance across the app and find what is
missing. Four read-only audits (API/database, React rendering, 3D rendering,
page load) ran against `d7eb71b`; each finding was checked against source before
any change. The native splat renderer, its workers and generated data were
excluded: T-627/T-628 own them and public splats remain on hold.

Implemented on `claude/cool-tesla-90zlcp`, with measurements and the ranked list
of remaining opportunities in the
[performance review](../reports/performance-review-2026-09-24.md):

- Web bundles: side-effect-free shared contracts, named Sentry imports, on-demand
  GDTF/MVR archive reader, and a separate `three-webgpu` vendor chunk. The
  panorama tour's route payload fell from 633 KB to 329 KB gzip; the homepage's
  from 175 KB to 75 KB; the deferred Sentry chunk from 144 KB to 26 KB.
- Homepage and hallkeeper images now come from display-sized WebP ladders of the
  same supplied photographs; throttled phone LCP 24.9 s → 5.1 s and transfer
  7.34 MB → 0.97 MB on the local production build. The crest is a 21 KB WebP.
- `vercel.json` caches versioned models and hashed voice clips immutably and
  other public files briefly. The quiz no longer fails when Google Fonts is
  unreachable (reproduced before, rendered after).
- Planner: fewer per-frame store notifications and re-renders during drags and
  marquee selection; hidden wall click planes; fades rebuild materials only on a
  blending change; Grand Hall textures survive camera gestures. The desktop
  placement-rule sweep that runs on every drag move is grid-indexed
  (1,287 items: 209.6 → 1.45 ms, identical results under a 500-layout property
  test), and select-all drags no longer rescan the layout per item. The
  Diary's render and drag costs were reduced in a separate commit.
- API: one-statement fast path for linked sign-ins; optional networkless Clerk
  verification (`CLERK_JWT_KEY`); CORS preflight caching; JSON/text response
  compression with binary routes opted out; 60 s Neon idle connections;
  set-based planner batch saves (150 objects: 158 → 11 statements).

Decisions and constraints recorded in the report: no change to planner render
resolution (a prior founder-reviewed choice), furniture model simplification or
transmission glass without visual acceptance, or splat-owned data. Layout
revision retention is a data-retention decision left open.

Verification used disposable PostgreSQL 16 clusters on the suites' own loopback
ports (55476–55478), never a shared database. Results are in the report.

Blake then asked for the best choices for maximum performance and a push to
`master`. No other release was active (master unchanged since `d7eb71b`; open
PRs target `release/r1` or are documentation). Before pushing, the production
build ran the planner, tour, hallkeeper, quiz, landing, pricing and navigation
E2E specs in `vite preview`; every failure also occurs on the `master` build in
this container (details in the report). The push to `master` was then refused
by this session's permission system, so the branch waits for Blake's decision.
Live verification is also not possible from here: the session's network policy
blocks `venviewer.com` and `api.venviewer.com`.

The founder mandate rules out a lower-resolution canvas, blurred motion and
visibly simpler furniture, so "maximum performance" here means invisible work.
Measured and rejected: error-bounded furniture simplification removes under 5%
of triangles at 0.5 mm (texture and normal detail sets the budget), and
distance-based detail levels only reach about 2× at errors that are sub-pixel
beyond 20 m. The next wave (instanced place settings, merged Grand Hall
ornaments, a mounted room shell, a direct furniture instancing path, cached
name plates, self-hosted fonts, display-sized images, earlier staff code
download, a faster planner start-up and API hot paths) follows in later commits.

Defects found in passing and left open are listed in the report (Diary enquiry
tray window, phantom template selection, instanced furniture culling); the next
wave addresses them.

### Second wave

Six agents worked in isolated worktrees; each commit was reviewed, integrated
on the branch and re-verified. Measurements and the full list are in the
report's "Second wave" section.

- Planner: dinner covers share one geometry and material per part (1,000 → 5
  each; select-all drag commit ≈24 → ≈7 ms); editable furniture draws from
  pooled instance buffers (drag-step commit 65 → 8.1 ms at 1,287 items); opaque
  Grand Hall ornaments draw as merged batches (overview 330 → 132 draws); the
  room shells stay mounted across camera gestures; name plate textures are
  shared. Instanced covers were built and rejected: they changed 148–2,082
  pixels per view. Merged ornaments differ in 1–41 isolated edge pixels per
  frame (float rounding); fades, x-ray and section views are pixel-identical.
- Loading: guarded staff pages download their code during the account check;
  the planner's draft lookups run together and a guest's chosen draft is not
  fetched twice; fonts are self-hosted; quiz and inventory images are
  display-sized.
- Fonts: `packages/web/scripts/self-host-google-fonts.mjs` mirrored Google's
  own files and rules (42 browser user agents probed); `provenance.json` and
  the OFL licences sit in `packages/web/src/styles/fonts/`. Firefox on Windows
  (faces without `MVAR`) and macOS (the static EB Garamond italic instance) keep
  their builds as user-agent overrides; Apple and Android builds differ only in
  tables those platforms do not use. Opera and Vivaldi on Windows, Yandex, Edge
  for Android and Firefox on Windows 7/8.1 were served static instances and now
  get the variable faces as designed. Font preloads were measured and rejected
  (render-blocking in Chrome).
- Images: `packages/web/scripts/build-image-ladders.mjs` (sharp, Lanczos3 on
  premultiplied alpha, near-lossless WebP) writes deterministic copies with a
  `provenance.json`. The cleaned room plans stay PNG: a re-encode would drop
  their C2PA manifest recording them as AI-generated.
- API: rate limiting per verified user (it was per office IP) and 429 instead of
  500 when limited; access checks skip stored thumbnails; the Diary tray asks
  for open enquiries, newest first, for its venue; phase-graph payloads are
  omitted for the web; linked-layout summaries are batched with a fallback for
  an older API; dashboard totals are computed in SQL; migration 0071 adds two
  foreign-key indexes. A pipeline above £1,000,000 no longer makes the
  dashboard answer 500. The Neon connect timeout was withheld: driver 0.10.4
  can crash the process on a stalled handshake.

Still open: the dashboard's Enquiries list shows only the default 20 rows (an
ordering and paging decision), device frame measurements, compressed furniture
downloads, and the master push, which needs Blake.
