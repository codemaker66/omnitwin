## **STOP: the v1 frontier is not a room-only runtime**

The original `grand-hall-big-model-sog-fine-v1` contract bound the highest
detail eleven-member XGRIDS frontier. Subsequent room-scope review established
that those bytes cannot prove an individual closed Grand Hall: camera/source
membership is not a closed boundary, and portal interfaces remain unresolved.

Accordingly, every earlier registration, credential, staging, rehearsal,
upload, deployment, and QA instruction for those v1 bytes is superseded. Use
`docs/operations/grand-hall-frontier-intake-runbook.md` only for the current
retirement status; it contains no executable v1 procedure.

## Successor v2 runtime evidence contract

An exact Grand Hall runtime may be admitted only by one immutable
`venviewer.grand-hall-room-only-runtime-evidence.v2` object that binds:

- the source frontier receipt above;
- a separately human-accepted room-membership artifact;
- a separately human-accepted closed room volume, explicitly not camera
  membership alone;
- a human-accepted decision resolving every portal/interface;
- a complete accepted panorama mask set;
- a complete accepted source-point mask;
- a distinct derived cropped-output inventory and its ordered member digest;
- a human reviewer and review instant; and
- a runtime policy prohibiting generated fill, procedural or synthesized pixel
  replacement, nadir crowns, neighbouring-room pixels, and facade assets,
  while requiring masked/unknown regions to remain transparent or unknown.

The cropped inventory must not contain any legacy frontier member byte
identity, including renamed, reordered, subset, or mixed use. Every member is
bounded to 16 MiB so admission and authenticated preview share the same safe
limit. The atomic browser package is additionally bounded to 128 MiB, 32
members, 1,000,000 Gaussians per member, and 8,000,000 Gaussians total. These
bounds retain headroom above the 106,479,738-byte / 6,019,684-Gaussian source
frontier while preventing manifest-driven allocations or request fan-out at
OOM scale. Cropping may yield a different member count, sizes, hashes, and
Gaussian count; those values belong to the accepted v2 output and must never
be copied from the source frontier.

## Current trust and serving behavior

The production accepted-evidence SHA-256 trust root is deliberately `null`.
Synthetic v2 fixtures exist only in tests and are not real acceptance
artifacts. Therefore no current Grand Hall package is runtime-admissible.

API registration, canonical/latest discovery, and authenticated preview reject
missing, legacy, pending, wrong-scope, wrong-mask, wrong-boundary, wrong-portal,
or non-`human_reviewed` evidence before private-object reads. The verified
Trades Hall Grand Hall web route likewise fails closed: it does not fall back
to generic/legacy bytes, procedural architecture, neighbouring rooms, facade,
or generated pixels.

The former v1 credential and intake entry points are code-blocked with
`GRAND_HALL_V1_INTAKE_RETIRED`. The read-only source validator remains only for
lineage diagnostics and explicitly reports `runtimeAdmissible: false`.

## Unblocking rule

Do not provision an intake capability or author a new operational runbook until
the real distinct cropped output and every required human acceptance exist.
After that gate, review a new digest-derived v2 object prefix and purpose-built
tooling. Never reuse or rename the v1 bytes, prefix, credentials, or package.
